# 需求描述

## 项目目标

开发一个支持大文件透传下载的 Web 服务组件，核心目标是严格控制前后端内存占用，无论下载多大的文件，内存消耗必须保持在常数级（O(1)）。

该组件需封装为 Spring Boot Starter，可供其他 Java Web 系统直接引入使用。

## 用户需求

### 目标用户
- Java Web 系统开发者
- 需要代理下载大文件的系统集成方

### 核心需求
1. **流式代理下载**：后端作为代理，拉取目标文件流并直接写入响应流，禁止将文件全量或大块装入内存
2. **断点续传**：支持 HTTP Range 请求，下载中断后可从断点继续
3. **前端流式落盘**：前端利用 Streams API 和 File System Access API，边接收数据块边写入本地磁盘
4. **实时反馈**：在前端界面实时展示下载进度（%）和下载速率（MB/s 或 KB/s）
5. **开箱即用**：打成 JAR 包，其他项目引入依赖即可使用

## 功能需求

### 后端功能
| 功能 | 说明 |
|------|------|
| 流式代理下载 | 固定 buffer 大小流式传输，零内存缓存 |
| Range 请求支持 | 解析 Range 请求头，返回 206 Partial Content |
| Header 透传 | 透传 Content-Length、Content-Type |
| 文件大小限制 | 可配置最大下载文件大小 |
| 超时控制 | 可配置连接超时和读取超时 |

### 前端功能
| 功能 | 说明 |
|------|------|
| 目录选择 | 使用 File System Access API 选择保存位置 |
| 流式写入 | 边接收边写入磁盘，不拼接 Blob |
| 进度展示 | 实时显示下载进度百分比 |
| 速率计算 | 实时计算并显示下载速率 |
| 断点续传 | 暂停/继续下载，支持从断点恢复 |
| 状态管理 | 显示当前下载状态（空闲/下载中/暂停/完成/错误） |

## 业务场景

### 场景一：大文件代理下载
用户通过系统下载远程服务器上的大文件（如 10GB 视频文件），系统作为代理转发请求，内存占用始终保持在 8KB 左右。

### 场景二：网络不稳定环境下载
用户在下载过程中遇到网络中断，暂停下载后网络恢复，可从断点继续下载，无需重新开始。

### 场景三：多系统集成
其他 Java Web 系统需要下载功能，只需引入 starter 依赖并配置，即可获得完整的流式下载能力。
